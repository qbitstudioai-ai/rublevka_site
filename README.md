# Рублевка — сайт загородного комплекса

**[План проекта и статус этапов](docs/PLAN.md)**

**Главная бизнес-цель:** прямые продажи проживания — помогать гостям выбрать дом или номер и перейти к бронированию. Интерактивная сказочная книга привлекает и знакомит с комплексом; остальные услуги дополняют основной сценарий. Действующий сайт для изучения услуг и фактов: https://rublevka34.com/

## Концепция

**«Уехать из города, чтобы насладиться тишиной».**

- Визуальный стиль: древнерусская сказка, срубы, резное дерево, лес, теплый свет, фактуры пергамента.
- Подача: сайт как живая книга с главами, плавными переходами, деликатным параллаксом и отдельными 3D-эффектами.
- Ощущение: тишина, покой, уют, гостеприимство. Волшебство не должно мешать навигации и бронированию.
- **Не перегружать сайт текстом:** короткие содержательные блоки, выразительные изображения и понятные действия. Использовать реальные фото комплекса; художественные иллюстрации не выдавать за реальные объекты.
- Адаптивность, доступность, высокая скорость загрузки и корректная работа без тяжелых эффектов — обязательны.

## Основной функционал

- Проживание: каталог домов и номеров, характеристики, фото, цены, подбор и бронирование.
- Беседки, банный комплекс, два банкетных зала, ресторан и услуги: отдельные страницы, заявки и бронирование там, где это доступно.
- Интерактивная карта территории и фотогалерея.
- Афиша мероприятий с регистрацией; заявки на свадьбы, банкеты и корпоративы.
- Чат с администраторами; в дальнейшем — бот-помощник с передачей диалога человеку.
- Админ-панель: управление объектами, контентом, мероприятиями, заявками и обращениями. Личный кабинет гостя — отдельный этап.
- Бронирование проживания: предусмотреть выбор **Bnovo или TravelLine** через независимый адаптер; до подключения не показывать вымышленные цены, доступность или подтверждения. Источник истины — выбранный провайдер.

## SEO и поиск

**Задача:** добиваться максимально высоких позиций в Яндексе и Google по целевым региональным запросам; первое место не гарантируется.

Предварительные группы запросов для проверки спроса и распределения по страницам:
- «база отдыха Волгоград», «турбаза Волгоград», «загородный комплекс Волгоград»;
- «домики для отдыха Волгоград», «аренда дома из сруба Волгоград»;
- «аренда беседки Волгоград», «баня на базе отдыха Волгоград»;
- «банкетный зал Волгоград», «свадьба на базе отдыха Волгоград»;
- «отдых на Волге», «база отдыха на берегу Волги».

Требования:
- Отдельные индексируемые страницы под основные услуги и поисковые намерения; полезные, уникальные, **неперегруженные ключевыми словами** тексты.
- Уникальные `title`, `description`, `h1`; понятные URL, внутренние ссылки, корректные canonical, sitemap.xml и robots.txt.
- Семантическая разметка, структурированные данные по подходящим типам Schema.org, alt для изображений.
- Быстрая мобильная версия, Core Web Vitals, техническая индексируемость; настройка Яндекс Вебмастера и Google Search Console при запуске.
- Географию, цены, условия, характеристики и актуальность запросов сверять с администрацией и фактическими данными.

## Организация работы

- Концепция — основа; **шапка сайта, меню, ссылки и структура страниц будут уточняться по ходу проекта**.
- Функции и этапы внедрения утверждаются до разработки соответствующих модулей.
- VSCode разрабатывает локально и публикует изменения в GitHub для проверки. Репозиторий держать чистым: только код, необходимые ресурсы и актуальная документация.

## Локальная разработка

Требуется Node.js 20.9 или новее.

```bash
npm install
npm run dev
```

Проверка перед отправкой изменений:

```bash
npm run check
```

Архитектура и границы будущих модулей описаны в [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

### Мероприятия

`npm run dev` запускает основной сайт и оригинальное приложение регистрации. Для первого запуска установите зависимости обоих приложений. Для установленной версии SQLite требуется Node.js 22 или новее.

```powershell
npm ci
npm ci --prefix events-original --ignore-scripts
npm run dev -- --port 3270
```

Афиша открывается по адресу `http://localhost:3270/meropriyatiya`, панель — по `/meropriyatiya/admin`. Внутренний процесс афиши слушает только loopback на порту 3271. Локальная SQLite автоматически создаётся в `events-original/data` и заполняется публичным каталогом. Для локального входа задайте собственные `ADMIN_USERNAME`, `ADMIN_PASSWORD` и `ADMIN_SESSION_SECRET` в файле `events-original/.env.local`.

Развёртывание требует отдельного процесса оригинального приложения. Основной сайт передаёт ему запросы через `EVENTS_ORIGINAL_ORIGIN`. Публичный приём заявок закрыт.


### Панель сайта

Укажите `DATABASE_URL` и отдельный случайный секрет `SITE_ADMIN_SESSION_SECRET` длиной от 32 символов в окружении основного приложения. Команды миграции и первоначальной настройки запускайте с тем же `DATABASE_URL`.

```powershell
npm run db:migrate
npm run site:seed
npm run site:admin:create -- имя-администратора
```

CLI запросит пароль со скрытым вводом. Войдите по адресу `/admin/site`. Редактор сохраняет черновики и отправляет их на публикацию. Администратор публикует изменения, восстанавливает предыдущую версию и управляет сотрудниками.

Установите `CMS_ENABLED=true` перед запуском сайта, чтобы публичные страницы читали опубликованный контент. Без этой настройки сайт использует данные из репозитория. Для фотографий при локальном запуске используется `.cms-media/`. В production требуется абсолютный `CMS_MEDIA_DIR` на постоянном томе. Для локальной проверки с изолированной PostgreSQL можно запустить `node scripts/test-events-db.mjs --serve` в отдельном терминале и взять строку подключения из указанного им файла.
