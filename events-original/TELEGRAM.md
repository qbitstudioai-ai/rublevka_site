# Telegram-уведомления о регистрациях

После каждой успешной регистрации приложение отправляет сообщение в чат администрации через Telegram Bot API. Внешние сервисы (n8n и т.п.) не используются.

## Что приходит в Telegram

```
Новая регистрация на мероприятие «Новогодняя ночь»
https://meropriyatiya.allqbit.ru/admin/events/3/registrations/0b8f…-…
```

Только название мероприятия и ссылка на регистрацию в админпанели (адрес берётся из `APP_URL`). **Персональные данные в Telegram не отправляются:** ФИО, телефон, мессенджер, выбранные услуги и сумма остаются только в базе на сервере в России и видны в админке по ссылке. Telegram — зарубежный сервис, поэтому так не возникает трансграничной передачи персональных данных. Ссылка содержит случайный идентификатор регистрации, а не данные участника; без входа в админпанель по ней ничего не открыть.

## 1. Создать бота

1. Откройте в Telegram [@BotFather](https://t.me/BotFather).
2. Отправьте команду `/newbot`.
3. Введите имя бота (например, «Рублёвка — регистрации») и username, оканчивающийся на `bot`.

## 2. Получить токен

BotFather пришлёт токен вида `1234567890:AAH...`. Это пароль бота: не пересылайте его и не публикуйте. Если токен утёк, выпустите новый командой `/revoke` в BotFather.

## 3. Узнать chat_id

Уведомления можно получать в личном чате с ботом или в группе администрации.

**Группа** (удобно, если уведомления нужны нескольким людям):

1. Добавьте бота в группу.
2. Напишите в группе любое сообщение, например `/start`.
3. Откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates` (вставьте свой токен вместо `<ТОКЕН>`).
4. Найдите `"chat":{"id":-100...` — это и есть `chat_id` группы (обычно начинается с `-100`).

**Личный чат:** напишите боту `/start` и так же откройте `getUpdates` — `chat.id` будет положительным числом.

Если `getUpdates` возвращает пустой список, отправьте в чат ещё одно сообщение и обновите страницу.

## 4. Заполнить переменные окружения

В `.env.local` (локально) или в настройках окружения сервера:

```env
TELEGRAM_BOT_TOKEN=токен_от_BotFather
TELEGRAM_CHAT_ID=-1001234567890
```

После изменения перезапустите приложение. Токен хранится только в переменных окружения: его нет в базе, в админпанели и в логах.

## 5. Проверить из админпанели

1. Откройте `/admin/settings`.
2. В разделе «Уведомления о регистрациях» должно быть «Telegram настроен».
3. Нажмите «Отправить тестовое уведомление» — в чат придёт сообщение «✅ Тестовое уведомление».

Если показана ошибка:

- «Telegram не принял токен бота» — проверьте `TELEGRAM_BOT_TOKEN`;
- «бот не может написать в этот чат» — проверьте `TELEGRAM_CHAT_ID` и что бот добавлен в группу;
- «ошибка подключения» — сервер не смог связаться с Telegram (сеть, firewall); попробуйте позже.

**Хостинг в России.** У некоторых провайдеров (так ведёт себя Timeweb, где развёрнут meropriyatiya.allqbit.ru) подключение к `api.telegram.org` выборочно обрывается: часть попыток проходит, часть зависает. Поэтому одна отправка делает до 3 попыток новым соединением (тайм-аут попытки 6 с), а неотправленное остаётся в очереди и повторяется cron каждые 10 минут. Если ошибок всё равно много, Telegram API можно направить через прокси за пределами РФ: Node.js 24 поддерживает `NODE_USE_ENV_PROXY=1` и `HTTPS_PROXY=http://…` в `production.env`.

## Как это работает

- Сообщение формируется из сохранённой регистрации и snapshots услуг — с теми названиями и ценами, которые видел участник.
- Вместе с регистрацией в базе создаётся запись очереди (outbox). Сразу после ответа участнику делается попытка отправки; если Telegram недоступен, регистрация всё равно сохранена, а уведомление остаётся в очереди.
- Повтор: `npm run telegram:retry` (на сервере — по cron каждые 10 минут, см. `DEPLOYMENT.md`) или кнопка «Повторить неотправленные» в `/admin/settings`. После 5 неудачных попыток уведомление помечается «не удалось» и повторяется только вручную (`npm run telegram:retry -- --include-failed` или кнопка).
- Отправленное уведомление повторно не отправляется. Если сервер остановился в момент отправки, сообщение может прийти дважды (доставка «хотя бы один раз»).
- В базе и логах хранится только краткая причина ошибки — без токена.
