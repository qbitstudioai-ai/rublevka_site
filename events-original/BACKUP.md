# Резервное копирование

## Что сохраняется

Один архив `rublevka-backup-ГГГГММДД-ЧЧММССZ.tar.gz` (время в UTC) в каталоге `BACKUP_DIR`:

```text
manifest.json              дата, список миграций, число мероприятий, регистраций и файлов
database/rublevka.sqlite   согласованная копия базы
uploads/<uuid>.webp|png    все загруженные фото и QR
```

В архив **не попадают**: `.env*`, исходный код, `node_modules`, посторонние файлы из каталога загрузок.

## Как запустить

```bash
npm run backup                                              # локально
docker compose -f docker-compose.production.yml exec -T app node scripts/backup.mjs   # в Docker
```

Нужны переменные `DATABASE_PATH`, `UPLOADS_DIR`, `BACKUP_DIR`; `BACKUP_RETENTION_DAYS` — по умолчанию 30.

## Согласованность SQLite и WAL

- База копируется через **online backup API SQLite** (`better-sqlite3` → `sqlite3_backup`), а не копированием файла. Копия включает данные, которые ещё находятся в `-wal`, и не мешает работающему приложению: регистрации продолжаются во время бэкапа.
- Копия переводится в обычный режим журнала (без `-wal`/`-shm`) и проходит `PRAGMA integrity_check`; при ошибке архив не создаётся.
- Сначала снимается база, затем копируются загрузки: файлы, на которые ссылается снимок, к этому моменту уже существуют (файл записывается до транзакции, которая на него ссылается).
- Архив пишется во временный `*.partial` и переименовывается только после успешного завершения — неполных архивов с «настоящим» именем не бывает.

## Хранение (retention)

После **успешного** создания нового архива удаляются архивы этого приложения старше `BACKUP_RETENTION_DAYS` дней. Возраст определяется по метке времени в имени файла. Удаляются только файлы, имя которых точно соответствует шаблону `rublevka-backup-ГГГГММДД-ЧЧММССZ.tar.gz`; любые другие файлы в `BACKUP_DIR` не трогаются.

## Рекомендации

- Запускать ежедневно через cron (см. `DEPLOYMENT.md`).
- Регулярно копировать архивы за пределы сервера (другой диск, облачное хранилище): volume с бэкапами на том же сервере не защищает от потери сервера.
- Периодически проверять восстановление по `RESTORE.md` на тестовой машине.
- Архив содержит персональные данные участников (ФИО, телефоны) — храните его с ограниченным доступом.
